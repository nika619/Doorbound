# Security

Doorbound runs in people's homes and hears about their children's mornings, so it is built to keep that to itself. This page walks a 19-point pre-launch checklist for apps built with AI help, then five money-and-legal risks, item by item, with the code that backs each answer. "N/A" means the app has no such surface, and says why.

To report a problem, open a private security advisory on the GitHub repository rather than a public issue.

## What there is to protect

- **Data:** each household's routines (names and step lengths), the last 9 real durations per person and step, and today's departure. Stored in one JSON file on the server's own disk. No accounts, no email addresses, no payment details, no audio.
- **Surfaces:** `POST /mcp` (the tools Alexa+ calls), `GET /api/board` (state for a screen), `GET /board` (the board page, no data in it), `GET /` (a simulator, served only on the machine itself), `GET /healthz`.
- **Who may call:** Alexa+ with the bearer token you configure; screens with the screen key; anyone on the machine itself when it listens only on loopback.

## The checklist

| # | Item | Status | How |
|---|---|---|---|
| 1 | Row-level security | N/A | No database. One household per server, in one file: `src/server/store.ts`. |
| 2 | Auth on every route | Pass | `/mcp` checks the bearer token on every request, compared in constant time (SHA-256 both sides, then `timingSafeEqual`): `tokenMatches` in `src/server/guard.ts`. `/api/board` needs the screen key or the token whenever the server is reachable beyond loopback. The server **refuses to start** on a non-loopback address without a token of 32+ characters and an allow-list of host names: `src/server/main.ts`, configuration block. `/board` is a page with no data in it; the data comes from `/api/board`. |
| 3 | Never trust the front end | Pass | Every tool input is a schema with bounds (`zod`, `src/server/tools.ts`). People are matched by name against the household, never taken as ids. The server computes every plan and every chance; the board only displays them. The file on disk is treated as input too and validated on load; a file that fails is set aside, never silently used or deleted (`Store.open`). |
| 4 | Rate limiting | Pass | Token buckets per client: MCP 20/s (burst 40), board data 5/s (burst 10), pages 5/s (burst 20). The client map is capped (10,000, least recently seen evicted), so the limiter cannot be used to exhaust memory: `RateLimiter` in `src/server/guard.ts`. Behind a proxy, `TRUST_PROXY=1` keys on the forwarded address. |
| 5 | Sanitize user input | Pass | Length and shape limits on every string and number (`LIMITS` in `src/server/store.ts`: 8 people, 15 steps, 32-character names). The board writes text with `textContent` only, never `innerHTML` (`src/board/board.ts`), so a name cannot become markup. |
| 6 | Parameterized queries | N/A | No SQL or other query language. |
| 7 | Lock down CORS | Pass | No CORS headers are sent at all, so browsers block cross-origin reads. `/mcp` also validates `Host` and `Origin` (DNS-rebinding protection) with the MCP SDK's validators: loopback names only when local, the configured allow-lists otherwise. Checked by `npm run smoke` (a foreign Origin gets 403). |
| 8 | Force HTTPS | Pass | `compose.yaml` puts the server behind Caddy, which serves HTTPS only for the configured domain and fetches and renews its certificate; HTTP is redirected. With `TRUST_PROXY=1` and `X-Forwarded-Proto: https`, the server also sends HSTS (`baseHeaders`). On loopback (development) it speaks plain HTTP to the machine itself only. |
| 9 | IDOR | Pass | Clients never name objects by id. A tool says "Isha is done"; the server finds Isha in its own household and her current step in its own state. There is one household per server, so there is no other household's data to reach. |
| 10 | Debug off in production | Pass | Errors reach the client as "Something went wrong." with no stack or detail; the log gets the message only (`src/server/main.ts`). Tool failures are plain sentences that say what to do instead. The simulator, a development tool, is served only on loopback. |
| 11 | CAPTCHA on public forms | N/A | No public forms. Nothing unauthenticated writes data or sends mail. |
| 12 | Log admin actions | Pass | Append-only audit of every change: time, tool, outcome, the person concerned, and a hashed client address. Never arguments beyond the person, never a credential. Rotated at 1 MB so it stays bounded: `src/server/audit.ts`. |
| 13 | Private storage | Pass | The data directory is created `0700` and files are written `0600`. Writes are atomic (write, then rename) and coalesced, so a crash never leaves half a file (`Store.save`). No uploads, no downloads, no public buckets. |
| 14 | Hide admin pages properly | N/A | No admin pages. The only privileged page, the simulator, is not served beyond loopback at all. |
| 15 | Update vulnerable packages | Pass | `npm audit`: 0 vulnerabilities (re-run Oct 16, 2026, with every dev dependency). Five runtime dependencies (the MCP SDK packages and zod), versions locked in `package-lock.json`. Dependabot (`.github/dependabot.yml`) checks npm, the CI actions and the Docker base image weekly, and CI installs with scripts off. |
| 16 | File upload types | N/A | No file uploads. |
| 17 | AI security review | Pass | Claude reviewed the server code route by route while writing this page (Oct 15, 2026) and found nothing beyond what this table lists. A complement to items 1-16, not a substitute. |
| 18 | Security headers | Pass | Every response: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy` and `-Resource-Policy: same-origin`, a `Permissions-Policy` that turns off camera, location, microphone, payment and USB (`baseHeaders`). Pages add a hash-only Content Security Policy: `default-src 'none'`, scripts and styles allowed only by the SHA-256 of the exact blocks built into the page, no `unsafe-inline`, no framing (`pageCsp`; hashes from `scripts/build.mjs`). Checked by `npm run smoke`. |
| 19 | Verify webhook signatures | N/A | No webhooks. |

## Money and legal exposure

Five risks of AI-built apps that cost money or invite lawsuits without anyone breaking in.

| # | Risk | Status | How |
|---|---|---|---|
| 20 | A traffic spike becomes a bandwidth bill | Pass | Self-hosted, so no per-gigabyte platform bill by default. Everything served is small: the board is one 79 kB (gzipped) page, an unchanged poll is an empty 204, and every client is rate-limited. No media files. If you put it on a metered host, front it with a CDN or WAF and set the host's usage alerts and caps. |
| 21 | Accessibility (WCAG 2.1 AA) | Pass, with one limit | Every control is a real `<button>` with a visible focus ring; the Done button's accessible name says whose step it marks ("Done: Isha"), and on the first tap it becomes "Tap again to confirm". Each row has a screen-reader sentence and changes are announced through an `aria-live` region. No meaning is carried by colour alone (statuses and chances are words and numbers). Text contrast is at least 4.5:1 for small text and 3:1 for large labels, measured (the faint label colour was raised from 2.7:1 to 4.2:1 for that). Reduced motion turns off every animation. The limit: with eight people on one screen the Done buttons shrink below the 44 px touch-target guideline; voice still works for everyone. |
| 22 | A public key that reads every user's data | N/A | No database and no keys in any page. The screen key only lets a TV read its own household's board, and it travels in the URL fragment, which browsers never send to a server. |
| 23 | Messages sent without consent | N/A | Doorbound sends no SMS, email or notifications. Alexa speaks only in reply to the household. |
| 24 | Runaway compute | Pass | No recursion and no fan-out: a re-plan is capped at 20,000 plans (worst measured 99 ms at the household limits), the server makes no outbound calls, and everything kept is bounded: 8 people x 15 steps, 9 samples per step, an audit log rotated at 1 MB. |

## Beyond the checklist

- **Account linking (many households on one server):** authorization code with PKCE S256 only (plain refused); redirect URIs matched exactly, and an unregistered one is shown an error, never redirected to; codes are signed, bound to client, redirect URI and challenge, last ten minutes and work once; the linking form is signed and bound to its request (a POST nobody rendered is refused); the page has no script, one hashed stylesheet, `frame-ancestors 'none'` and no referrer. Household keys are 128 random bits, shown once and stored only as a fingerprint (a hash names the household's folder). Every token names one household and reads only its folder; Alexa+'s service token can list tools but runs none. Refresh tokens last 90 days and are revoked by rotating the signing key. Failed client logins, not Alexa+'s normal token traffic, count against the strict limit. Audit lines name the household's fingerprint. All of it runs end to end in the smoke test in CI.
- **Children's data, kept small and short:** first names and step times only; "delete everything Doorbound knows about us" erases a household after a spoken yes; households idle for 180 days (configurable) are deleted daily; audit lines hold hashes of people and devices, never names; the add-on sends nothing to any third party (the simulator's optional model, below, is a developer tool on one machine).
- **A TV's link:** it reads its household's board and can mark a step done (a Fire TV remote's OK), nothing else: no settings, no other household, no tokens. A wrong key is refused, even on the server's own machine, and the key is in the URL fragment, which never reaches a server log.
- **The front-door hook:** `POST /hooks/left` ends a household's morning only with that household's signed hook key (or AUTH_TOKEN for the server's own), only from 15 minutes before its leaving time, and is rate-limited. The key may travel in the query string because most door sensors and home routines can only call a URL; it opens nothing but that one action (it is not the TV key, nor a token), and rotating the signing key revokes it.
- **Alexa+ sign-in (OAuth 2.1 client credentials):** client id and secret compared in constant time, both always checked; accepted by HTTP Basic or in the body, never both and never in the query string; tokens last an hour, are HMAC-signed with `OAUTH_SIGNING_KEY`, a key only the server knows (Amazon holds the client secret, so knowing that is not enough to mint a household's token; rotating the signing key revokes every token, TV link and door key), bound to this server's `/mcp` (RFC 8707) and checked in constant time; errors follow RFC 6749 5.2; the token endpoint is rate-limited to one a second per client and audited; discovery documents follow RFC 8414 and RFC 9728. Tested in `oauth.test.ts` and end to end in the smoke test, in CI against the locked-down container.
- **Secrets** live only in environment variables. `.env` and the data directory are git-ignored; nothing secret is in the repository or in any page.
- **The simulator's model key:** `ANTHROPIC_API_KEY` is read from `.env` on the developer's own machine at run time and never built into a page, the bundle or the image (`.env` and `.env.*` are in `.gitignore` and `.dockerignore`). A local pre-commit hook refuses `.env` files and anything shaped like a key, and CI fails, without printing it, if one ever reaches the repository. `/sim/understand`, the only route that uses the key, answers on the server's own machine only (404 beyond it), checks its input and is rate-limited; it sends Anthropic what was typed or said, the household's first names and the time, nothing else.
- **The container:** the image ships Node and the built files only (no sources, no `node_modules`, npm removed) and runs as the unprivileged `node` user. `compose.yaml` runs it with a read-only filesystem except the household volume, every Linux capability dropped, `no-new-privileges`, and a 256 MB memory cap; only Caddy is published to the network.
- **Resource limits:** request bodies over 64 KB are refused before parsing (413); headers time out at 10 s and requests at 15 s; at most 64 headers. A re-plan is bounded by a search budget (20,000 plans, then a greedy stand-in), so a large household cannot make one request run long.
- **The screen:** it reads state and, on a touch screen inside Alexa+, can mark a step done with two taps (so a brush against the screen does nothing). A TV can do the same with its remote, and nothing more (above).
- **Privacy by design:** no audio is stored or processed here (Alexa+ turns speech into tool calls); the only personal data is first names and how long steps take.
